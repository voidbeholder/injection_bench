# Prompt injection: слабые и сильные модели на AgentDojo

Скрипт прогоняет модели из OpenRouter через бенчмарк [AgentDojo](https://github.com/ethz-spylab/agentdojo) (ETH Zurich, NeurIPS 2024) и сводит метрики в одну таблицу. Задачи, тексты атак и проверки целиком берутся из AgentDojo: скрипт только подключает модели, выбирает подмножество задач и считает итог.

К лекции «Безопасность LLM- и агентных систем», раздел 2.5 «Насколько это решено?».

## Что измеряется

Агенту дают обычную задачу в одной из сред (банк, Slack, путешествия, рабочая почта), а в данные, которые он прочитает, подкладывают инъекцию. Результат проверяется **по состоянию среды**, а не по тексту ответа.

| Метрика | Что значит |
|---|---|
| `utility` | доля задач пользователя, решённых **без** атаки |
| `utility_under_attack` | доля задач, решённых, когда в данных есть инъекция |
| `asr` | доля эпизодов, где агент выполнил задачу атакующего (targeted attack success rate) |
| `attacker_task_doable` («атака выполнима») | может ли модель выполнить задачу атакующего, если попросить её напрямую, без инъекции. Если нет, низкий ASR может объясняться неумением, а не устойчивостью |

## Установка

Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и вставьте ключ из https://openrouter.ai/keys. В `.env` же меняются модели пресетов `weak` / `medium` / `strong`; подойдёт любая модель OpenRouter с поддержкой tools.

## Стенд в браузере

```bash
.venv\Scripts\python server.py
```

Откройте http://127.0.0.1:8770. Сервер слушает только localhost.

- **Слева — запуск.** Галочками выбираются модели (пресеты из `.env` или свой id), среда, атаки, защиты и размер выборки. Под формой сразу видно, сколько эпизодов это будет и какие задачи выбраны. Кнопка «Запустить», прогресс считается по эпизодам.
- **Справа — результаты.** Столбики utility, utility под атакой, ASR и «атака выполнима». В списке «прошлые запуски» можно открыть любой сохранённый прогон.
- **Клик по строке — эпизоды этой конфигурации.** Фильтры: атака удалась / не удалась / «готово» только на словах (агент написал об успехе, а проверка не прошла) / без атаки. Клик по эпизоду раскрывает его по шагам: запрос, вызовы инструментов с аргументами, ответы инструментов (шаг с инъекцией подсвечен красным), текст агента и итог проверки по состоянию среды.

Тексты из журналов показываются только как простой текст: без HTML, разметки и подгрузки картинок. Это та самая мера из лекции против утечки через вывод модели.

Одновременно идёт только один запуск. Тот же прогон есть и в консоли, как описано ниже.

## Запуск из консоли

Сначала посмотреть план и число эпизодов без вызовов API:

```bash
.venv\Scripts\python run_bench.py --dry-run --models weak strong --suites banking --user-tasks 5 --injection-tasks 3
```

Тот же прогон по-настоящему:

```bash
.venv\Scripts\python run_bench.py --models weak strong --suites banking --user-tasks 5 --injection-tasks 3
```

Полезные варианты:

```bash
# список атак и размеры сред
.venv\Scripts\python run_bench.py --list

# сравнить два шаблона атаки: «важное сообщение» и шаблон из InjecAgent
.venv\Scripts\python run_bench.py --models weak strong --attacks important_instructions_no_model_name injecagent --user-tasks 5 --injection-tasks 3

# включить защиту из AgentDojo и сравнить с её отсутствием
.venv\Scripts\python run_bench.py --models weak --defenses none spotlighting_with_delimiting repeat_user_prompt --user-tasks 5 --injection-tasks 3
```

Параметры:

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--models` | `weak strong` | пресеты или явные id моделей OpenRouter |
| `--suites` | `banking` | `banking`, `slack`, `travel`, `workspace` |
| `--attacks` | `important_instructions_no_model_name` | атаки AgentDojo, см. `--list`; `none` — только без атак |
| `--defenses` | `none` | `spotlighting_with_delimiting`, `repeat_user_prompt`, `tool_filter` |
| `--user-tasks`, `--injection-tasks` | все | число (случайная выборка с фиксированным `--seed`) или список id |
| `--force-rerun` | выкл. | иначе готовые эпизоды берутся из `runs/` и не оплачиваются повторно |

Журналы эпизодов удобно смотреть через `show_episode.py` (`--list` с фильтрами `--hijacked`, `--resisted`, `--claimed`; путь к файлу — разбор по шагам).

Итоговая таблица печатается в консоль и сохраняется в `results/summary-<время>.csv` и `.json`. Журнал каждого эпизода (все сообщения, вызовы инструментов, итог проверки) лежит в `runs/<модель>/<среда>/<задача>/<атака>/<задача атакующего>.json`. Эти журналы удобно показывать на семинаре.
